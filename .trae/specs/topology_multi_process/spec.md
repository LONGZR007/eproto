# eProto 拓扑多进程测试 - 产品需求文档

## 概述
- **摘要**：创建一个多进程测试系统，用于验证 eProto 协议在复杂网络拓扑结构中的通信功能，包括设备间的直接通信和通过其他设备的转发通信。
- **目的**：测试 eProto 协议在复杂网络拓扑中的可靠性和转发功能，确保所有设备之间能够正确通信。
- **目标用户**：eProto 协议开发者和测试人员。

## 目标
- 实现基于管道的多进程通信系统，模拟复杂网络拓扑结构
- 支持命令行发送消息和回复消息功能
- 验证设备间的直接通信和转发通信
- 确保所有设备之间能够正确通信

## 非目标（超出范围）
- 不实现实际的网络硬件连接
- 不测试性能和吞吐量
- 不实现图形用户界面

## 背景与上下文
- 基于现有的 multi_process 示例实现
- 使用 named pipes (FIFO) 进行进程间通信
- 拓扑结构参考 combined_topology.md 文件

## 功能需求
- **FR-1**：实现 5 个进程（A、B、C、D、E）模拟网络拓扑中的设备
- **FR-2**：每个进程支持命令行发送消息到指定设备
- **FR-3**：每个进程支持回复收到的消息
- **FR-4**：实现设备间的直接通信和转发通信
- **FR-5**：支持查看拓扑结构文档

## 非功能需求
- **NFR-1**：进程间通信使用 named pipes (FIFO)
- **NFR-2**：支持非阻塞 I/O 操作
- **NFR-3**：使用系统毫秒时间戳
- **NFR-4**：代码符合项目编码规范

## 约束
- **技术**：C 语言，使用 named pipes (FIFO) 进行进程间通信
- **依赖**：eProto 协议库

## 假设
- 所有进程在同一台机器上运行
- 管道文件权限设置正确
- 系统支持 named pipes

## 验收标准

### AC-1：多进程启动
- **给定**：所有进程编译完成
- **当**：启动所有进程
- **然后**：所有进程成功启动，无错误
- **验证**：`programmatic`

### AC-2：直接通信测试
- **给定**：进程 A 和 B 已启动
- **当**：A 发送消息到 B
- **然后**：B 收到消息并显示
- **验证**：`programmatic`

### AC-3：转发通信测试
- **给定**：所有进程已启动
- **当**：A 发送消息到 E（需要通过 B 转发）
- **然后**：E 收到消息并显示
- **验证**：`programmatic`

### AC-4：回复功能测试
- **给定**：所有进程已启动
- **当**：A 发送消息到 B 并请求回复
- **然后**：B 发送回复，A 收到回复
- **验证**：`programmatic`

### AC-5：拓扑文档可访问
- **给定**：拓扑测试目录已创建
- **当**：查看 topology_test/readme.md
- **然后**：文档包含完整的拓扑结构和挂载关系
- **验证**：`human-judgment`
