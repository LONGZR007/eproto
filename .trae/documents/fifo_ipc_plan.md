## 2. 实现计划

### 2.1 目标
- 将所有进程的IPC实现改为使用有名管道（FIFO）
- 确保进程间无依赖关系，支持任意启动顺序
- 保证通信功能正常，包括消息发送、接收和回复

### 2.2 具体步骤

#### 步骤1：更新process_c.c文件
- **修改IPC初始化**：将socket相关函数调用替换为FIFO函数
- **更新FIFO路径**：使用定义的FIFO路径常量
- **修改清理函数**：将`ipc_cleanup_sockets`替换为`ipc_cleanup_fifos`
- **更新连接逻辑**：使用`ipc_open_fifo`替代`ipc_connect_to_server`

#### 步骤2：验证所有进程的FIFO实现
- 确保所有进程都使用相同的FIFO路径定义
- 验证FIFO打开逻辑，确保无阻塞模式正确实现
- 检查错误处理机制

#### 步骤3：测试进程间通信
- **编译所有进程**：使用Makefile编译所有进程
- **测试启动顺序**：测试不同启动顺序下的通信情况
  - 顺序1：A → B → C
  - 顺序2：C → B → A
  - 顺序3：B → A → C
- **测试消息传递**：验证进程间能够正常发送和接收消息
- **测试回复功能**：验证带回复的消息能够正确处理

### 2.3 技术实现要点

#### FIFO创建与打开
- 使用`mkfifo`创建FIFO文件，已存在时忽略错误
- 以非阻塞模式打开FIFO（`O_RDWR | O_NONBLOCK`）
- 确保FIFO路径一致且可访问

#### 进程间无依赖实现
- 每个进程独立打开自己需要的FIFO通道
- 无阻塞模式确保进程启动时不会因FIFO未被另一方打开而阻塞
- 定期尝试读写操作，确保连接建立后能立即通信

#### 错误处理
- 处理FIFO创建错误（已存在时忽略）
- 处理读写操作的非阻塞错误（EAGAIN/EWOULDBLOCK）
- 确保资源正确释放（关闭FIFO文件描述符）

## 5. 风险评估

### 5.1 潜在风险
- **FIFO权限问题**：可能导致无法创建或打开FIFO
- **非阻塞模式下的性能**：需要适当的轮询机制
- **消息丢失**：非阻塞模式下可能出现消息丢失

### 5.2 风险缓解
- 设置正确的FIFO权限（0666）
- 使用合理的轮询间隔（10ms）
- 实现简单的消息重试机制
- 确保进程退出时清理FIFO文件
