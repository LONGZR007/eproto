# eProto 协议文档

## 1. 协议概述

### 1.1 协议名称
**eProto** - Embedded Protocol（嵌入式协议）

### 1.2 设计目的
eProto 是专为嵌入式系统设计的轻量级通信协议，主要用于：
- 多个设备之间的可靠通信
- 资源受限的嵌入式环境
- 支持多种总线（UART、SPI、I2C等）
- 提供可靠的重传机制和错误校验

### 1.3 协议优势
- **轻量级设计**：头部开销仅11字节，适合资源受限的嵌入式系统
- **可靠性保障**：内置CRC-16校验、重传机制和超时控制
- **设备寻址**：支持单设备通信和广播通信
- **多总线支持**：可轻松适配不同的物理层总线
- **握手机制**：支持设备间握手，确保通信链路建立
- **线程安全**：提供完整的锁机制，支持多线程环境

## 2. 协议帧格式

### 2.1 帧结构总览

eProto 帧由以下字段组成：

```
| 帧头(1) | 版本号(1) | 长度(2) | 包类型(1) | 源地址(1) | 目标地址(1) | 包ID(2) | 数据(n) | CRC(2) |
```

### 2.2 字段详细说明

#### 2.2.1 帧头 (Header)
- **长度**：1 字节
- **固定值**：0xAA
- **作用**：标识帧的起始位置，用于帧同步

#### 2.2.2 版本号 (Version)
- **长度**：1 字节
- **当前值**：0x01
- **作用**：标识协议版本，用于版本兼容性检查

#### 2.2.3 长度 (Length)
- **长度**：2 字节（大端序）
- **作用**：标识数据字段的长度（不包括帧头和CRC）
- **范围**：0 - 65535 字节

#### 2.2.4 包类型 (Packet Type)
- **长度**：1 字节
- **作用**：标识数据包的类型和属性

**包类型定义**：
| 值 | 名称 | 说明 |
|----|------|------|
| 0x00 | EPROTO_PACKET_TYPE_USER_SEND | 用户发送数据包 |
| 0x01 | EPROTO_PACKET_TYPE_USER_REPLY | 用户回复数据包 |
| 0x02 | EPROTO_PACKET_TYPE_PROTOCOL_ACK | 协议确认包 |

**包类型标志位**：
| 位 | 名称 | 说明 |
|----|------|------|
| bit 7 | RETRANSMIT_FLAG | 重传标志 (0x80) |
| bit 6 | HANDSHAKE_FLAG | 握手标志 (0x40) |

#### 2.2.5 源地址 (Source Address)
- **长度**：1 字节
- **作用**：标识发送设备的地址
- **范围**：0x00 - 0xFE
- **特殊值**：无（广播地址仅用于目标地址）

#### 2.2.6 目标地址 (Destination Address)
- **长度**：1 字节
- **作用**：标识接收设备的地址
- **范围**：0x00 - 0xFF
- **特殊值**：0xFF (EPROTO_BROADCAST_ADDRESS) - 广播地址，所有设备都会接收

#### 2.2.7 包ID (Packet ID)
- **长度**：2 字节（大端序）
- **作用**：唯一标识一个数据包，用于匹配请求和响应
- **范围**：0 - 65535

#### 2.2.8 数据 (Data)
- **长度**：0 - 65535 字节
- **作用**：承载实际的用户数据
- **说明**：该字段是可选的，长度可以为0

#### 2.2.9 CRC (Cyclic Redundancy Check)
- **长度**：2 字节（大端序）
- **算法**：CRC-16-CCITT
- **多项式**：0x1021
- **初始值**：0xFFFF
- **计算范围**：从帧头开始到数据字段结束的所有字节
- **作用**：验证帧的完整性

## 3. 字节序说明

eProto 协议采用**大端序**（Big-Endian）传输所有多字节字段。

### 3.1 大端序定义
大端序是指数据的高位字节存储在低地址，低位字节存储在高地址。

### 3.2 涉及大端序的字段
- **长度字段**（2字节）
- **包ID字段**（2字节）
- **CRC字段**（2字节）

### 3.3 大端序示例
假设长度字段值为 0x1234：
```
发送顺序：0x12 (高位) -> 0x34 (低位)
```

假设包ID为 0x5678：
```
发送顺序：0x56 (高位) -> 0x78 (低位)
```

## 4. 包类型详解

### 4.1 用户发送包 (USER_SEND)
- **包类型值**：0x00
- **用途**：发送用户数据，需要接收方回复
- **流程**：
  1. 发送方发送 USER_SEND 包
  2. 接收方接收数据后，发送 USER_REPLY 或 PROTOCOL_ACK
  3. 发送方等待回复，超时则重传

### 4.2 用户回复包 (USER_REPLY)
- **包类型值**：0x01
- **用途**：回复用户数据请求，包含用户数据
- **说明**：
  - 包ID必须与请求的 USER_SEND 包ID相同
  - 可以携带用户数据作为回复

### 4.3 协议确认包 (PROTOCOL_ACK)
- **包类型值**：0x02
- **用途**：协议层确认，不包含用户数据
- **说明**：
  - 包ID必须与请求的包ID相同
  - 数据字段长度为0
  - 用于简单的确认场景

## 5. 通信流程

### 5.1 正常单播通信流程

```
设备A (地址0x01)                    设备B (地址0x02)
     |                                    |
     |-- USER_SEND (ID=100) ------------>|
     |                                    |
     |<-- USER_REPLY (ID=100) ----------|
     |                                    |
```

### 5.2 超时重传流程

```
设备A (地址0x01)                    设备B (地址0x02)
     |                                    |
     |-- USER_SEND (ID=100) ------------>| (丢失)
     |                                    |
     |  等待超时...                       |
     |                                    |
     |-- USER_SEND (ID=100, RETRANSMIT) ->|
     |                                    |
     |<-- USER_REPLY (ID=100) ----------|
     |                                    |
```

### 5.3 广播通信流程

```
设备A (地址0x01)                    设备B (地址0x02)
     |                                    |
     |-- USER_SEND (ADDR=0xFF, no_wait)->|
     |                                    |
     |                                    |-- 处理数据
     |                                    |
     |  不等待回复                        |
     |                                    |
```

## 6. 错误处理

### 6.1 CRC 校验错误
- 当接收方检测到CRC错误时，丢弃该帧
- 统计连续CRC错误次数
- 连续错误达到阈值时，触发状态回调

### 6.2 超时处理
- 发送方在超时时间内未收到回复，触发重传
- 重传次数达到最大值时，通知发送失败

### 6.3 重发包检测
- 接收方通过包ID检测重复包
- 对于重复包，可以选择丢弃或重新处理

## 8. 示例帧

### 8.1 简单用户数据包

假设：
- 源地址：0x01
- 目标地址：0x02
- 包ID：0x0001
- 数据：[0x11, 0x22, 0x33]

**完整帧**：
```
AA 01 00 03 00 01 02 00 01 11 22 33 XX XX
```
- AA：帧头
- 01：版本号
- 00 03：长度（3字节数据）
- 00：包类型（USER_SEND）
- 01：源地址
- 02：目标地址
- 00 01：包ID
- 11 22 33：数据
- XX XX：CRC-16校验值

### 8.2 广播数据包

假设：
- 源地址：0x01
- 目标地址：0xFF（广播）
- 包ID：0x0002
- 数据：[0xBB, 0xCC]

**完整帧**：
```
AA 01 00 02 00 01 FF 00 02 BB CC XX XX
```

## 9. CRC-16-CCITT 计算

### 9.1 多项式
```
x^16 + x^12 + x^5 + 1 (0x1021)
```

### 9.2 初始值
```
0xFFFF
```

### 9.3 计算示例
```c
// 假设帧数据为：AA 01 00 03 00 01 02 00 01 11 22 33
// CRC 计算覆盖前12字节（不包括最后的CRC字段）
uint16_t crc = eproto_crc16_ccitt(frame_data, 12);
```

## 10. 注意事项

1. **地址唯一性**：每个设备在同一总线上应具有唯一的地址
2. **包ID管理**：包ID由发送方管理，确保在合理时间内不重复
3. **超时配置**：根据实际网络环境调整超时时间
4. **重传次数**：根据通信可靠性需求配置最大重传次数
5. **缓冲区大小**：确保接收缓冲区足够大以容纳最大帧
