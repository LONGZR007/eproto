# eProto 实现文档

## 1. 设计原理

### 1.1 协议设计目标

eProto 是一个专为嵌入式系统设计的轻量级通信协议，其设计目标包括：

- **可靠性**：确保数据在各种通信环境下的可靠传输
- **轻量级**：占用资源少，适合资源受限的嵌入式系统
- **可移植性**：通过抽象层设计，支持各种硬件平台
- **灵活性**：可根据具体应用场景进行配置和扩展

### 1.2 协议架构

eProto 采用分层设计架构，主要包括以下层次：

1. **应用层**：用户接口，提供数据发送和接收功能
2. **协议层**：处理数据包的封装、解析和管理
3. **总线层**：抽象物理总线接口，处理数据的实际传输
4. **系统层**：提供内存分配、时间戳、信号处理等系统服务

## 2. 核心组件

### 2.1 数据结构

#### 2.1.1 帧结构

eProto 的帧结构定义如下：

| 字段 | 长度（字节） | 描述 |
|------|-------------|------|
| 帧头 | 1 | 固定值 0xAA，标识帧的开始 |
| 版本号 | 1 | 协议版本号 |
| 长度 | 2 | 数据长度（不包括帧头、版本号、长度和CRC） |
| 包类型 | 1 | 包的类型（数据、确认、握手等） |
| 原地址 | 1 | 发送设备的地址 |
| 设备地址 | 1 | 目标设备的地址 |
| 包ID | 2 | 数据包的唯一标识符 |
| 数据 | N | 实际数据内容 |
| CRC | 2 | CRC16校验和 |

#### 2.1.2 核心结构体

1. **eproto_t**：eProto 实例结构体
   - 包含用户函数和总线管理器数组

2. **eproto_bus_manager_t**：总线管理结构体
   - 管理总线接口、接收缓冲区、帧解析器等
   - 处理数据的发送和接收

3. **eproto_user_functions_t**：用户函数结构体
   - 提供内存分配、信号处理、锁机制等接口

4. **eproto_bus_t**：总线接口结构体
   - 定义发送和接收函数

5. **eproto_frame_parser_t**：帧解析器结构体
   - 负责解析接收到的数据帧

### 2.2 核心模块

#### 2.2.1 帧解析器

帧解析器负责从接收到的数据流中解析出完整的协议帧：

- 识别帧头
- 解析帧长度
- 验证CRC校验和
- 提取数据包内容

#### 2.2.2 数据包管理

数据包管理模块负责：

- 数据包的创建和销毁
- 发送队列的管理
- 等待应答队列的管理
- 超时处理和重发机制

#### 2.2.3 总线管理

总线管理模块负责：

- 总线的初始化和配置
- 设备地址的管理
- 数据的发送和接收
- 状态回调和错误处理

#### 2.2.4 CRC校验

CRC校验模块负责：

- 计算数据的CRC16校验和
- 验证接收到的数据的CRC校验和
- 确保数据传输的完整性

## 3. 数据流

### 3.1 数据发送流程

1. **用户调用发送函数**：用户调用 `eproto_send` 或 `eproto_send_ex` 函数发送数据
2. **创建数据包**：根据用户提供的数据创建数据包
3. **添加到发送队列**：将数据包添加到发送队列
4. **发送数据**：从发送队列取出数据包，封装成帧并通过总线发送
5. **等待应答**：如果需要应答，将数据包添加到等待应答队列
6. **处理应答**：收到应答后，从等待应答队列中移除数据包并调用回调函数
7. **超时处理**：如果超时未收到应答，重新发送数据包或调用回调函数

### 3.2 数据接收流程

1. **接收数据**：通过总线接口接收数据
2. **解析帧**：使用帧解析器解析接收到的数据
3. **验证CRC**：验证帧的CRC校验和
4. **处理数据包**：根据包类型处理数据包
   - 如果是数据帧，调用接收回调函数
   - 如果是确认帧，从等待应答队列中移除对应的数据包
   - 如果是握手帧，处理握手逻辑
5. **发送应答**：对于需要应答的数据帧，发送确认帧

## 4. 实现细节

### 4.1 内存管理

eProto 使用用户提供的内存分配函数进行内存管理：

- 用户需要实现 `malloc` 和 `free` 函数
- 数据包和节点的内存由用户提供的内存分配函数分配
- 确保内存的正确分配和释放，避免内存泄漏

### 4.2 时间管理

eProto 使用用户提供的时间戳函数进行时间管理：

- 用户需要实现 `get_timestamp` 函数，返回当前时间戳（毫秒）
- 时间戳用于计算超时时间和重发间隔
- 确保时间戳的准确性和单调性

### 4.3 信号处理

eProto 使用用户提供的信号处理函数进行同步：

- 用户需要实现 `signal_wait` 和 `signal_send` 函数
- 信号用于通知线程有数据需要处理
- 确保信号处理的正确性和及时性

### 4.4 锁机制

eProto 使用用户提供的锁函数保证线程安全：

- 用户需要实现 `lock` 和 `unlock` 函数
- 锁用于保护共享资源，避免并发访问冲突
- 确保锁的正确使用，避免死锁

### 4.5 错误处理

eProto 提供了完善的错误处理机制：

- 错误码定义：`EPROTO_OK`、`EPROTO_ERROR_CRC`、`EPROTO_ERROR_TIMEOUT` 等
- 状态回调：通过 `status_callback` 通知状态变化
- 错误恢复：支持自动重发和超时处理

## 5. 多实例支持

eProto 支持多个实例同时运行：

- 每个实例有自己的总线管理器和配置
- 实例之间相互独立，不影响彼此的运行
- 可以在不同的线程或进程中使用不同的实例

## 6. 握手功能

eProto 提供了可选的握手功能：

- 用于建立设备间的连接
- 确保设备在线状态
- 可以配置是否需要握手

## 7. 配置选项

eProto 通过配置文件 `eproto_config.h` 提供了丰富的配置选项：

- `EPROTO_MAX_BUS_COUNT`：最大总线数量
- `EPROTO_MAX_DESTINATION_DEVICES`：每个总线的最大目标设备数量
- `EPROTO_BUFFER_SIZE`：缓冲区大小
- `EPROTO_MAX_PACKET_SIZE`：最大数据包大小
- `EPROTO_DEFAULT_TIMEOUT`：默认超时时间
- `EPROTO_DEFAULT_RETRY_COUNT`：默认重发次数
- `EPROTO_ENABLE_HANDSHAKE`：是否启用握手功能

## 8. 性能优化

### 8.1 内存优化

- 使用固定大小的缓冲区，避免动态内存分配
- 合理设置缓冲区大小，平衡内存使用和性能
- 及时释放不再使用的内存，避免内存泄漏

### 8.2 时间优化

- 优化时间戳获取函数，减少时间获取的开销
- 合理设置超时时间和重发间隔，平衡可靠性和性能
- 使用高效的算法处理数据包队列，减少时间复杂度

### 8.3 通信优化

- 合理设计数据包大小，减少通信开销
- 使用广播功能减少不必要的点对点通信
- 优化CRC计算算法，减少计算开销

## 9. 扩展性

eProto 设计具有良好的扩展性：

- 支持添加新的总线类型
- 支持添加新的设备类型
- 支持扩展协议功能
- 支持自定义回调函数

## 10. 实现示例

### 10.1 初始化示例

```c
// 定义用户函数
eproto_user_functions_t user_functions = {
    .malloc = my_malloc,
    .free = my_free,
    .signal_wait = my_signal_wait,
    .signal_send = my_signal_send,
    .lock = my_lock,
    .unlock = my_unlock,
    .get_timestamp = my_get_timestamp,
    .timeout_timestamp = 0
};

// 初始化eProto实例
eproto_t eproto_inst;
eproto_error_t error = eproto_init(&eproto_inst, &user_functions);
```

### 10.2 添加总线示例

```c
// 定义总线接口
eproto_bus_t bus = {
    .send = my_bus_send,
    .receive = my_bus_receive
};

// 添加总线
error = eproto_add_bus(&eproto_inst, self_address, &bus, rx_buffer, sizeof(rx_buffer),
                       "my_bus", handshake_callback, status_callback);
```

### 10.3 发送数据示例

```c
// 发送数据
uint8_t data[] = {0x01, 0x02, 0x03, 0x04, 0x05};
error = eproto_send(&eproto_inst, destination_address, data, sizeof(data),
                   send_callback, NULL, 1);
```

### 10.4 接收数据处理示例

```c
// 在中断或轮询中调用
void uart_interrupt_handler(void) {
    uint8_t data = uart_read();
    eproto_receive_data(&eproto_inst, bus_address, &data, 1);
}
```

### 10.5 定时处理示例

```c
// 定期调用
void timer_interrupt_handler(void) {
    eproto_process(&eproto_inst);
}
```
