# 实时交互 MTU 支持方案

## 1. 方案概述

本方案为 eProto 嵌入式协议提供完整的 MTU（Maximum Transmission Unit）支持，核心包含四大模块：

| 模块 | 功能 | 说明 |
|------|------|------|
| **PMTUD** | 实时 MTU 探测与协商 | Path MTU Discovery，动态发现路径最小 MTU |
| **Fragment** | 分包发送与收包重组 | 超过 MTU 的自动分片与接收端重组 |
| **Forward** | 转发 MTU 适配 | 跨总线转发时自动按目标 MTU 分包 |
| **Monitor** | MTU 运行时监控 | 实时 MTU 更新与通知 |

## 2. 架构设计

┌──────────────────────────────────────────────────────────────────┐

│                       MTU Manager                                │
│  ┌─────────────┐  ┌──────────────┐  ┌────────────────────────┐  │

│  │  (探测协商) │  │ (分包重组)   │  │  (转发时自动分片)      │  │

## 3. 扩展协议帧格式

### 3.1 新增包类型（使用保留 bit）

在原有包类型字节上扩展：

| bit | 原有含义 | 扩展 |
|-----|---------|------|
| bit2 | **新增** | 1=MTU 控制包 (PMTUD探测/响应) |
| bit3 | **新增** | 1=分片数据包 |
| bit4 | **新增** | 1=分片最后一包 |

### 3.2 分片帧扩展（在 data 前增加分片头）

当包类型 bit3=1 时，data 前增加 **4 字节分片头**：

```
| 分片头(4) | 原始用户数据(N) |
```

分片头格式：

| 字段 | 长度 | 含义 |
|------|------|------|
| fragment_id | 2 字节 | 同一个大包的唯一标识（递增） |
| fragment_index | 1 字节 | 当前分片序号 (0 ~ max-1) |
| total_fragments | 1 字节 | 总分片数 |

### 3.3 PMTUD 探测包格式（包类型 bit2=1）

| 字段 | 长度 | 含义 |
|------|------|------|
| probe_mtu | 2 字节 | 探测使用的 MTU 值 |
| current_mtu | 2 字节 | 探测方当前 MTU |
| probe_type | 1 字节 | 0=REQUEST, 1=REPLY, 2=TOO_BIG |
| reserved | 1 字节 | 保留 |

探测请求的 data 会填充到探测 MTU 大小，模拟大包传输。

## 4. 核心流程

### 4.1 发送流程（集成到 eproto_send）

```
用户调用 eproto_send(dst, data, len)
        │
        ▼
  查询 MTU 数据库 ──► 无记录？──► 使用初始 MTU，后台发起 PMTUD 探测
        │
        ▼
  len <= MTU？──► 是 ──► 直接发送原有帧
        │ 否
        ▼
  Fragment.split(data, len, mtu)
        │
        ▼
  生成 N 个分片帧 (fragment_id 相同, index 递增)
        │
        ▼
  依次入队发送（利用现有 eproto_send_queue 流程）
```

### 4.2 接收流程（集成到帧处理）

```
收到帧 ──► 检查包类型 bit3 (分片标志)
        │
   bit3 = 0 ──► 原有处理流程
        │ bit3 = 1
        ▼
  提取分片头 ──► 根据 fragment_id 查找重组上下文
        │
        ▼
  将分片加入重组缓冲区
        │
        ▼
  所有分片到齐？──► 否 ──► 更新超时定时器，等待后续分片
        │ 是
        ▼
  重组完整数据 ──► 调用 receive_callback
```

### 4.3 PMTUD 探测流程

```
发送方                              接收方
  │                                   │
  │── 构造 PMTUD probe (MTU=X) ──────►│
  │                                   │── 能接收吗？
  │                                   │   是 ──► 回复 REPLY(MTU=Y)
  │                                   │   否 ──► 回复 TOO_BIG(MTU=实际最大值)
  │◄─────── REPLY / TOO_BIG ─────────│
  │                                   │
  │ 根据响应更新 MTU 数据库          │ 更新 MTU 数据库（交换双方 MTU）
  │                                   │
  │ 继续探测（二分法逼近最优 MTU）    │
```

### 4.4 转发流程

```
转发节点收到帧 (从总线A)
        │
        ▼
  查询目标总线B 的 MTU
        │
        ▼
  帧总长(含封装后扩展) <= MTU_B？──► 是 ──► 直接转发
        │ 否
        ▼
  Fragment.split(frame_payload, mtu_b)
        │
        ▼
  生成分片帧，从总线B 发送
```

## 5. MTU 动态更新机制

- **初始值**：每个总线配置 `initial_mtu`（默认 1280，可调大）
- **协商后**：PMTUD 完成后更新为双方最小值
- **运行时调整**：
  - 连续 3 次 ACK 超时 → 自动将 MTU 减半（拥塞/路径变化）
  - 连续 5 次大包成功发送 → 逐步上调 MTU（+10% 或 +固定值）
- **主动探测**：空闲超过 `probe_interval_ms` 自动触发 PMTUD

## 6. 关键配置参数

```c
// 在 eproto_config.h 中新增
#define EPROTO_MTU_ENABLE               1       // 启用 MTU 功能
#define EPROTO_MTU_DEFAULT              1280    // 默认 MTU
#define EPROTO_MTU_MIN                  64      // 最小 MTU（小于此值不再分片）
#define EPROTO_MTU_MAX                  65000   // 最大 MTU（受协议长度限制）
#define EPROTO_MTU_PROBE_INTERVAL_MS    10000   // 主动探测间隔
#define EPROTO_MTU_REASSEMBLY_TIMEOUT_MS 5000  // 重组超时
#define EPROTO_MTU_MAX_REASSEMBLY_CONTEXTS 8   // 最大并发重组数
#define EPROTO_MTU_PROBE_RETRY          3       // 探测重试次数
```

## 7. 与现有 eProto 的集成点

| 现有接口 | MTU 集成方式 |
|---------|-------------|
| `eproto_send_ex` | 在入队前检查 MTU，必要时分片 |
| `eproto_process_user_send_packet` | 增加分片重组逻辑 |
| `eproto_process_protocol_ack_packet` | 解析 PMTUD 响应包类型 |
| `eproto_forward_frame` | 转发前按目标 MTU 分片 |
| `eproto_init` | 初始化 MTU 数据库 |
| `eproto_process` | 增加重组超时检查 + PMTUD 周期探测 |

## 8. 错误处理

| 场景 | 处理方式 |
|------|---------|
| 分片丢失导致重组超时 | 超时后清理上下文，调用回调通知应用层 |
| 探测失败超过重试次数 | 保持当前 MTU 不变，记录警告日志 |
| MTU 降到 MIN 以下 | 锁定为 MIN，不再降 |
| 重组缓冲区溢出 | 丢弃最早的重组上下文 |
| 转发时 MTU 更小 | 自动在转发端重新分片 |

## 9. 性能考量

- **分片开销**：每包增加 4 字节分片头 + 额外协议帧头，建议 MTU >= 128
- **重组内存**：最大并发重组数可配置，避免内存溢出
- **线程安全**：MTU 数据库使用 eProto 现有 lock/unlock 机制保护
- **零拷贝**：分片时数据引用而非复制（直到真正发送时才拷贝）
